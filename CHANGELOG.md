# Changelog

All notable changes to the **Paste backend**. Format based on [Keep a Changelog](https://keepachangelog.com); versioning per [SemVer](https://semver.org).

## [Unreleased]

### Added
- **Phase 3 — Revisions**: metadata-only history, single snapshots, computed unified diffs (jsdiff), append-only restore with metadata restore and no-op-when-identical; locked pastes expose revisions via the redacted X-Paste-Password header.
- **Phase 4 — Discovery**: title/description FTS (generated tsvector + partial GIN, modeled via Unsupported so future migrations never drop it), latest/popular feeds with database-level leak protection, trending (48h aggregates -> bounded zset, 5-min recompute), language facets, keyset cursor pagination, public profile pastes.
- **Phase 5 — Developer API**: hashed pb_ API keys (show-once, revoke-only, verified-email gate), bearer auth, daily per-key quotas, buffered usage capture + summaries, Idempotency-Key replay store on paste creation (409/422 semantics), OpenAPI 3.1 + Swagger UI.
- **Phase 6 — Collections & bookmarks**: owner-scoped slugs, ordered membership with transactional compaction, restricted-item rendering WITHOUT paste ids (leak rule), viewability-gated bookmarking.
- **Phase 7 — Analytics & embeds**: paste/user stats + 30-day series, denormalized storage counter with nightly reconcile, server-rendered embeds (highlight.js escaping, strict CSP, frame-ancestors *), share-token endpoints.
- **Phase 8 — Abuse & admin**: reports with auto-unlist heuristic + duplicate-cluster signals, suspension lifecycle (tx session/key revocation), moderator deletes, hard purge, IP-ban enforcement on anonymous writes, append-only audit trail, Turnstile CAPTCHA point (fail-closed).
- **Phase 9 — Hardening**: security consolidation suite (cookie/header hygiene, SQLi inertness, traversal, 413, unicode byte accounting, enumeration uniformity, secret-leak scans), k6 smoke profile, backup/restore tooling — drill PASSED (18 tables restored).
- Sequential integration-file execution (shared Redis state safety); non-TTY migration authoring helper (scripts/make-migration.cjs).

### Fixed
- pastes.id widened to VARCHAR(64) — custom slugs are the id (P2000 caught by tests; D-003).
- List envelopes aligned to the spec: { data, pagination: { cursor, hasMore } }.
- OAuth redirect_uri built with the /callback suffix; PKCE verified against mock providers.
- **Phase 2 — Paste core** (gate suites green: burn concurrency, flush crash recovery, expiry race):
  - Paste CRUD with the full visibility policy (public/unlisted/private), password protection + unlock, central access-policy service.
  - Expiration: query-side live filter (volatile now() only in queries), idempotent BullMQ expire/purge jobs (6-day delay cap), 5-minute AUTHORITATIVE sweeper, tombstone retention purges (7/30 days).
  - Atomic burn-after-read (guarded UPDATE + content nulling in one transaction) and exact synchronous max_views enforcement via guarded raw SQL.
  - Anonymous management tokens hashed in `paste_tokens` (shown once, X-Management-Token header); share tokens on private pastes.
  - View counting: Redis-buffered INCR + HLL, 60 s exactly-once flush with RENAME-to-inflight crash recovery, hourly monotonic unique-visitor flush, daily aggregates.
  - Forks (fresh identity, attribution), raw/download endpoints, snapshot revisions with the 20-revision drop-oldest cap, anonymous per-IP daily quotas.
  - Worker fleet: expire, purge, analytics, maintenance (session/token sweeps, storage reconcile) with boot re-registration of repeatables.

### Changed
- **Prisma 6.19.3 → 7.10.1** (latest stable; 8 release candidates explicitly not adopted) — see `DECISIONS.md` D-002.
  - Adopted the new `prisma-client` generator: TypeScript ESM client emitted to `src/generated/prisma` (gitignored; regenerated by `postinstall` and in CI).
  - Introduced `prisma.config.ts` (Prisma 7 CLI configuration; loads `.env` via dotenv — Prisma 7 no longer auto-loads it).
  - Removed `datasource.url` from `schema.prisma` (no longer supported in Prisma 7): the connection URL now lives in `prisma.config.ts` (CLI/migrations) and in the `@prisma/adapter-pg` driver adapter (runtime, `src/lib/prisma.ts`).
  - Added `pg` + `@prisma/adapter-pg`; queries run through node-postgres with the query compiler — no native query engine binary.
  - Added `postinstall: prisma generate`; excluded generated code from ESLint.
  - Verified end-to-end: `prisma validate` ✔ · `prisma generate` ✔ · `prisma migrate status` recognizes existing Phase 0/1 migrations ✔ · TypeScript typecheck ✔ · 27 unit + 3 integration tests against real PostgreSQL ✔ · production build (generated client compiled into `dist`) ✔.

### Security
- **`npm audit` after upgrade — inspected, not assumed:**
  - The high-severity `deepmerge-ts` advisory (GHSA-ggr8-5vv4-36mx, via `@prisma/config` of Prisma 6) is **resolved**. Tree inspection confirms `deepmerge-ts` is absent (`npm ls deepmerge-ts` empty; audit no longer reports it).
  - Remaining **7 moderate** advisories are confined to the dev-only `typescript-eslint` → `minimatch@10` lint toolchain (no runtime exposure). No in-range fix exists — the suggested "fix" would downgrade typescript-eslint 8.44 → 8.36. Documented as accepted in `DECISIONS.md` D-002; revisit when typescript-eslint drops the vulnerable minimatch range.
